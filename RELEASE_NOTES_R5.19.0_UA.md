# Home Craft — сайт R5.19.0

Це **повний вихідний код сайту**, побудований на R5.18.6. Моди Minecraft та конфігурація світу в цьому пакеті не змінювалися.

## Що змінилося

- Уніфіковано шрифти, ширину контенту, вирівнювання, відступи, картки, форми, кнопки та адаптивне меню. Нові стилі — `public/experience.css`.
- Переписано тексти входу, реєстрації, підтримки, статусу, головної, завантажень і профілю під потреби гравців. Прибрано технічні деталі (шляхи файлів, heartbeat, client-side та інше) з публічних блоків. Адміністративні налаштування залишилися у панелі адміністратора.
- Додано `/forgot-password` і `/reset-password`, API `POST /api/auth/password/forgot` та `POST /api/auth/password/reset`.
- Відновлення: випадковий токен (32 байти), тільки SHA-256 від токена в `data/runtime.json`, дійсність 30 хвилин, одноразовість, ліміт частоти звернень, відповідь без розкриття існування email, завершення активних сесій сайту і Minecraft після успішної зміни.
- Відновлення використовує Nodemailer 10.2.0. Немає SMTP — сервер повертає зрозумілу тимчасову недоступність; лист не імітується.
- Запит на відновлення генерує посилання з HTTPS-адреси `PUBLIC_SITE_URL`, не з HTTP Host; токен передається у URL-фрагменті та відразу очищається із адресного рядка.
- Захищено API від виведення внутрішніх деталей несподіваних помилок на публіку.

## Налаштування email

У конфігурацію сайту **на сервері**, не в публічні файли, додати:

```env
PUBLIC_SITE_URL=https://homecraft-mc.pp.ua
HOMECRAFT_SMTP_HOST=smtp.example.com
HOMECRAFT_SMTP_PORT=587
HOMECRAFT_SMTP_USER=no-reply@example.com
HOMECRAFT_SMTP_PASSWORD=ваш-пароль-додатку
HOMECRAFT_SMTP_FROM=no-reply@example.com
```

- Порт 587 — STARTTLS обов'язковий; 465 — TLS відразу.
- Логін/пароль SMTP не копіювати в репозиторій. Для Gmail часто потрібний пароль застосунку з увімкненою двофакторною автентифікацією або окремий поштовий сервіс з SMTP.
- Адреса сайту для відновлення має бути HTTPS і відповідати справжньому домену.
- Для доставки на зовнішні поштові скриньки налаштувати SPF, DKIM та DMARC для домену відправника.
- Може знадобитися дозволити **вихідне SMTP-з'єднання** на хостингу.

## Розгортання

1. Зберегти резервні копії `data/users.json`, `data/runtime.json` та `data/characters.json`.
2. Замінити вихідники сайту, залишивши **власні** `data/`, `config/` і `.env` без перезапису.
3. Docker: `docker compose build --no-cache site && docker compose up -d site`. Dockerfile встановлює `nodemailer` на етапі збірки.
4. Без Docker: Node.js 20+; `npm install --omit=dev` та `npm start` (рекомендовано Node.js 24).
5. Перевірити `/forgot-password`: запит на *існуючу* email-адресу та реальну доставку листа. Зробити повторний вхід з новим паролем і впевнитися, що старі сеанси завершені.

## Перевірки

- `node --check` — для серверного та браузерного JS.
- Локально виконано інтеграційні HTTP-перевірки реєстрації, запиту на відновлення, одноразового токена, зміни пароля, завершення сесій та входу з новим паролем із **тестовим поштовим транспортом**.
- Переглянуто HTML/CSS на настільному й мобільному розмірах: без горизонтальної прокрутки.
- Фактична доставка листа зовнішнім SMTP, бойове розгортання та робота під реальним доменом **не перевірялися**.
