# HomeCraft R5.15.2 — виправлення аварії авторизації (22.10.2026)

## Причина

`ServerAuthGuard.onServerTick` перебирає живий `PlayerList.getPlayers()`.
При закінченні 60 секунд `disconnectAuthTimeout()` синхронно відключає гравця, що
може змінити цей самий ArrayList і спричинити `ConcurrentModificationException`.
У журналі аварія вказує на ServerAuthGuard.java:158 після auth-timeout-disconnect.

## Що змінено

- `ServerAuthGuard` перебирає знімок списку гравців, а не змінюваний список.
- Такий самий захист додано в цикл вимкнення сервера та розсилки скінів.
- У порту NeoForge 26.3 підвищено версію Auth до `1.0.34-alpha.26.3.10+mc26.3-neoforge`.
- Auth JAR оновлено і в `mods`, і в `client-mods` пакета Minecraft,
  а також у `client-mods` пакета сайту. Map, Guild та Spawn Protection не змінені.
- Оскільки у середовищі доступна тільки Java 21 і відсутній Gradle 9.2.1,
  виконано точковий байткод-патч **оригінального Java 25 JAR**: invokeinterface
  `List.iterator()` замінено на рівноцінну статичну функцію знімка списку.
  Довжина інструкцій та всі відступи байткоду залишились незмінними. Допоміжний
  клас скомпільовано Java 21 (сумісний із Java 25), усі вихідні файли оновлено.

## Перед розгортанням

1. Зробити резервні копії світу, server config, власників персонажів, site data/config.
2. Зупинити Minecraft. **Видалити старий** `homecraftauth` з `mods` та `client-mods`;
   покласти новий файл `homecraftauth-neoforge-26.3-1.0.34-alpha.26.3.10+mc26.3-neoforge.jar`. Не запускати обидві версії одночасно.
3. Оновити SITE з окремого архіву, зберігши дані та секрети, не імпортувати заново DNS.
4. Перезапустити Minecraft; відтворити авторизацію з тайм-аутом 60 секунд.
   Очікувано: кік гравця без падіння сервера.
5. Перевірити повторний вхід, авторизацію, завантаження клієнтських модів, NPC/гільдії,
   та відсутність конфлікту зі старими JAR.

## Межі перевірок

Доступні статичні перевірки класів `javap`, контроль метаданих/версій, ZIP CRC,
SHA-256 та синхронності JAR у двох архівах. **Повний запуск NeoForge 26.3 на
Java 25 не виконувався**. Статичні перевірки не доводять відсутність runtime-багів.

Інші записи логу:
- `io.netty.channel.kqueue.Native` (`Only supported on OSX/BSD`) — проблема вибору
  або пробного завантаження мережевого транспорту Netty на Linux; не причина
  описаної аварії, бо сервер доходить до `Done` та приймає гравців.
- `online-mode=false` — Minecraft не перевіряє ліцензійні ідентифікатори;
  для публічного сервера потрібно окремо перевірити модель довіри / захист UUID.
- `api=` для Guild у логах — пустий endpoint. Упевнитись у працездатності
  приватного `config/homecraft-connection.properties` і інтеграцій.
- `grep: invalid matcher ...` — помилка зовнішнього startup-скрипта Pterodactyl;
  скрипт не включено до цих двох архівів, змінити Egg/Startup за місцем.

## DNS для входу за доменом (додаткова можливість)

У SITE/cloudflare/homecraft-mc.pp.ua.zone додано два записи:
`play A 51.83.184.222` (виключно DNS-only) і
`_minecraft._tcp SRV 0 5 25618 play.homecraft-mc.pp.ua.`.
Після **окремого внесення цих двох записів у Cloudflare** Java-клієнт Minecraft
має знаходити сервер за `homecraft-mc.pp.ua` без явного порту.
Існуючий A-запис кореневого домену залишається сайтом 149.202.57.156 (Proxied).
Не імпортуйте весь DNS файл повторно в непорожню зону без перевірки: це може
перезаписати поточні записи. Піддомен `play` не має бути Proxied.
Ці зміни не вмикають і не перевіряють DNS автоматично — потрібна дія в Cloudflare.
