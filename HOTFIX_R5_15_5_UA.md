# HomeCraft R5.15.5 — стабільніший вхід і діагностика API

## Зміни, які входять до JAR і вихідників

1. **AuthRequestState:** після успішного запиту до сайту GUI очікує підтвердження Minecraft-сервера до 14 секунд. Якщо пакет втрачено, поля стають доступними для повторного входу. Це тільки зняття блокування інтерфейсу, **не** автоматична авторизація й **не** продовження серверних 60 секунд.
2. **Ідентичність:** логінний запит використовує нік активного гравця Minecraft, а не профілю лаунчера; UUID береться з активного підключення. Без ніку/UUID HTTP-запит не виконується.
3. **Безпека пароля:** HTTP запити із паролями до публічних адрес заборонено. HTTPS — обов'язковий для зовнішніх доменів; HTTP дозволено лише для localhost і валідних приватних IPv4 мереж (локальна розробка). HTTP-перенаправлення не пересилаються автоматично.
4. **Перевірка токена:** сервер відрізняє неправильний serverSecret, прострочений токен, відхилений персонаж, HTTP 404 і 5xx — без показу токена чи секрету.
5. **Сайт:** `/api/minecraft/session/validate` повертає структурований `errorCode`: `SERVER_SECRET_INVALID`, `TOKEN_EXPIRED`, `IDENTITY_NOT_ALLOWED`; позитивний API-контракт збережено.
6. **Повідомлення входу:** форма показує повідомлення, передане сервером під час відкриття.

## Сумісність і встановлення

- Minecraft **26.3**, NeoForge **26.3.0.95**, серверний JDK **25**. Сайт — Node.js >=18, фактичний образ Node 24.
- Зробити резервну копію `world/`, `config/`, баз сайту і файлу `.env` перед заміною. Не стирати робочі конфіги.
- Зупинити сервер Minecraft, видалити **попередній Home Craft Auth JAR**, встановити новий із `mods/`; інші 3 HomeCraft-моди не змінювалися.
- На клієнті оновити Auth із `client-mods/` без паралельних старих копій; сайт деплоїти штатним `sh deploy.sh` без підміни `.env`.
- `serverSecret` у сайті й `config/homecraft-connection.properties` має збігатися, інакше буде `SERVER_SECRET_INVALID`. Не публікувати секрети.

## Ручна перевірка на сервері

1. Авторизація існуючим акаунтом і нова реєстрація; перевірити створення профілю, вибір точки появи й права доступу.
2. На клієнті вказати неправильний HTTPS URL; отримати зрозумілу помилку без завислої кнопки.
3. Імітувати відсутність відповіді сервера після надсилання токена; через 14 с форма дозволяє нову спробу. Серверні 60 с залишаються чинними.
4. Тимчасово зіпсувати **лише на тестовій інсталяції** serverSecret: побачити помилку про розбіжність секретів, без авторизації.
5. Прострочений одноразовий токен — відмова; перевірка невідповідного UUID — відмова; повторне підключення після тайм-ауту не призводить до крашу.
6. Перевірити, що клієнт не передає пароль на публічну `http://` адресу, а `https://` працює.

## Межі перевірки

Оновлені класи GUI і серверної HTTP-перевірки патчені байткодом на базі R5.15.4; pure-Java класи зібрані `javac --release 21` і сумісні із Java 25 JVM. Повної збірки NeoForge 26.3 (Gradle/JDK 25) і реального запуску тут **не було**. Перевірки синтаксису, JAR-структури та логіки pure-Java не гарантують відсутності runtime-регресій.
